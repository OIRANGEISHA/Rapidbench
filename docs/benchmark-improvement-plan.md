# Benchmark 可信度改进计划

基线：`baf36fd` / RapidBench 1.0.4 Beta 5。开始日期：2026-09-12。

## 目标与边界

逐步把快速微基准完善为可解释、可复验的分项性能评估。先保证计算与计时正确，再扩大负载覆盖；不以达到理论峰值、其他软件分数或固定排名为验收目标。

- 保留现有 CPU 吞吐负载、分数单位和默认快速测试。新负载不得静默替换旧分数。
- 不新增第三方依赖，不更新工具链；工具、缓存、构建和测试证据只存放在 `H:\test`。
- 不改包名、签名、现有公开 Tag 或 Release；本计划不包含 GitHub 发布。
- 当前开发先记录在 Unreleased；引入新测试功能或评分口径时，发布版本至少升 Minor，正式版本号在发布前确认。
- 真实设备仅以当次实际执行为准。当前可用：PJZ110 / Snapdragon 8 Elite / Adreno 830；其他厂商 GPU、老机和十核设备不能声称真机通过。
- 每一阶段独立验证。第一阶段未完成正确性验证前，不把新负载纳入对外成绩。

## 阶段 1：正确性修复（开发验证完成）

- [x] GPU：所有计算着色器正确应用 16 区输出偏移；覆盖 1/2/16/17/32 次 dispatch 与回绕。
- [x] GPU：增加计时之外的结果校验，检查实际写入区域、已知计算结果或明确披露的重复性验证；拒绝 NaN/Inf、未写入和错误输出。
- [x] GPU：逐一验证可用的 8/12/16 累加器版本，不仅验证自动选择的最快版本；计量常量与 shader 保持一致。
- [x] CPU：消除 worker 校验值的跨线程非同步读写，不改变 CPU 工作量和计分公式。
- [x] 回归：原生测试、着色器结构检查、Flutter 检查与测试、Debug 构建。
- [x] 样机：运行原生 GPU/CPU 回归并保存日志；单独区分原生真机测试与 App 安装后的端到端测试。

第一阶段不调整 Memory/Storage 的算法和 UI。若修复暴露现有着色器的非有限输出，仅修复可观察输出与验证所必需的部分，并记录成绩可比性边界。

## 阶段 2：负载代表性（进行中）

- [x] CPU 增加独立的应用型测试入口：确定性排序/文本解析/图像处理，每项有固定输入、正确性 oracle 和明确吞吐单位。
- [ ] 后续评估压缩负载的必要性与方法，再决定是否新增；不使用人为加权综合分数。
- [x] 明确现有新多 worker 子项是独立任务吞吐，不显示为共享任务协作倍率。
- [ ] 实现独立的共享任务协作测试，记录固定总任务量，不能用增加总工作量的 rate 冒充加速比。
- [x] 保留原 CPU 分数；应用型子项先独立报告，不在缺少跨设备校准时生成综合分数。
- [ ] Memory 增加随机 pointer-chasing 延迟及工作集大小扫描；使用确定性单环，防止预取和编译器删除，计数依赖访存次数。
- [ ] Memory 增加 1/2/4/全核的线程规模扫描；显示实际工作集、有效数据量和 Copy 双向口径，低内存降级可见。
- [x] CPU 新入口保持现有绿色、卡片风格；320px、1/2/3 倍字体及大数字测试通过。
- [x] 按用户要求取消新子项的核心/簇选择：Single 自动选最高性能目标核，Multi 全部 present 核心每核一个 worker；原 CPU 选择器保留，真机验证互不影响。
- [ ] Memory 新入口沿用布局风格，并补齐相应布局/溢出测试。

## 阶段 3：结果可比性（待阶段 2）

- [ ] 为每次结果绑定 schema/算法版本、测试模式、时长、工作集、worker 数、实际 affinity 状态。
- [ ] GPU 同时保留 GPU 活动时间和 Host 时间，明确整次测试中出现过的回退，不能只显示最后一个批次的模式。
- [ ] Storage 完成后仍能查看 Direct/Buffered、块大小、QD、线程数；区分 I/O 吞吐与最终同步等待。
- [ ] SQLite 明确 500 行事务、WAL/NORMAL 和行数/时长停止条件；如改为固定时长，单独提高方法版本。
- [ ] 记录 Android 热状态、可用的温控余量、电池/充电状态；不可读时显示 unknown，不推算温度或功耗。
- [ ] 提供本地结果导出，避免导出序列号、凭据等隐私字段；增加结果格式与兼容测试。

## 阶段 4：持续性与统计（待阶段 3）

- [ ] 保留 Quick 默认模式，增加可选持续测试（先考虑 60 秒）及三轮重复测试。
- [ ] 报告各轮原始结果、中位数、范围/离散度和持续曲线，不自动挑最高分替代最终成绩。
- [ ] 明确 Peak 窗口，标记热状态变化、后台中断与 affinity 降级；取消后保留已完成数据但不当作完整测试。
- [ ] 全局互斥、Stop、后台停止、恢复、资源释放以及大字体布局全部回归。
