## Added / 新增

- Optional CPU application tests, individually runnable in a collapsible section:
  65,536-key `std::sort` (Mkeys/s), 8,192 fixed-schema ASCII JSON records (MB/s),
  and a 1024×1024 grayscale Sobel image filter (MPix/s).
- Single automatically targets the detected highest-performance core (capacity,
  then maximum frequency). Multi creates one independent worker per present CPU,
  not a fixed eight-worker pool. The legacy CPU core/cluster selectors remain,
  but cannot change these new application tests.
- Each item warms up for 700 ms and measures for 3 seconds. Full output/reference
  comparison is outside timing; final throughput includes every counted batch's
  actual completion time. Stop preserves only verified partial results; restart
  clears the current item. Global exclusivity and background-stop rules apply.
- 三项新增负载分别显示吞吐和单位，不合成总分，不计入原 CPU 主分数或 Scaling。
  单核自动选检测到的最高性能核，多核全部 present 核心每核一个 worker；没有核心/簇选项。
  预热 700 ms、测量 3 秒；停止/重跑和后台取消继续使用全局互斥，回退与部分结果明确标注。

Method details and limitations: [CPU application method](../cpu-application-method.md).
JSON is a restricted fixed-schema parser, not a generic browser/Unicode/DOM test.
Multi measures independent-job throughput, not acceleration of one shared task.

## Fixed and measurement compatibility / 修复与分数可比性

- Correct the output-region offset in the eight-chain FP32/FP16, INT32 and Mixed
  shaders. Bound the Mixed final bit conversion to avoid NaN/Inf outputs.
- Validate each available FP variant before measurement and samples in every
  written output region afterwards. FP/INT/memory use independent CPU references;
  Mixed uses finite mathematical bounds and same-device repeatability, not a
  cross-driver bit-exact oracle. Readback synchronization and validation are untimed.
- Invalid GPU output clears the provisional result. Measured Stop validates
  completed batches; preparation-time Stop and restart do not retain stale scores.
- Publish legacy CPU worker checksums atomically, removing the identified
  cross-thread read/write race without altering its workload or score formula.
- GPU 方法为 `gpu-throughput-v2`，CPU 新子项方法为 `cpu-application-v1`。
  GPU 输出寻址和校验方式发生变化，旧版 GPU 成绩不能与本版直接横向比较；请统一方法版本重测。
  原 CPU 分数算法和单位不变；Memory/Storage 测试和计量不变。
- Existing published FFI layouts and test IDs remain intact. The new CPU API is
  additive with structure-size/version checks; internal pre-release development
  request layouts were not published and are not supported by the final API.

## Real-device boundary / 真机边界

Physical device: OnePlus PJZ110, Snapdragon 8 Elite / Adreno 830, Android 16.

## Storage coverage / 存储覆盖

All 11 IDs are retained: sequential read/write (1/2, Direct QD8; Buffered Q1T1
fallback), 4K Q1T1 (3/4), 4K Q8T1 (5/6), 4K Q1T4 (7/8), SQLite Insert/Update/Delete
(9/11/10). Direct paths are exercised on the phone; forced Buffered route selection
is simulated, not a forced buffered device run. Post-write fdatasync is excluded
from throughput and not yet retained as a separate result field. SQLite uses
WAL/NORMAL, 500-row transactions; Insert/Delete can hit row caps before 3 seconds.
