## Scope and baseline

This is a stability and measurement-accounting patch, based on public Beta 4
commit `71c6f9d90b0f4b397f7ed4430e9f8717b68fadd1`. Work was isolated on
`geisha/beta5-stability`; the earlier local Beta 4 history was preserved on
`geisha/beta4-local-backup`. Public Beta 4 tags and assets are not modified.

- One application-wide lease covers CPU, Memory, Storage and GPU preparation,
  warm-up, measurement, multi-item sequences, stop and cleanup. Other pages
  remain browsable while their start controls are disabled.
- Backgrounding requests a cooperative stop, cancels remaining sequence items,
  and keeps ownership until native work finishes. Foregrounding does not resume
  the run automatically.
- Native bridge failures destroy and join the affected engine before allowing
  another module to start. The affected controller requires an App restart;
  ordinary native terminal errors do not permanently disable the controller.
- Memory final throughput uses actual completion timestamps for all counted
  passes. It no longer truncates the denominator at the requested deadline or
  includes coordinator polling and join delays.
- Memory working buffers and the Storage scratch file are reclaimed before
  their terminal snapshots can release the lease.
- Release signing uses the supplied keystore and alias instead of checking the
  environment but then selecting the Debug signing configuration.
- English and Chinese Storage documentation now matches the actual Direct and
  Buffered routes; no Storage test was added, removed or renumbered.

## Measurement compatibility

CPU/GPU workloads, Storage workloads, FFI ABI and dependencies are unchanged.
Read and Write count payload once; system `memcpy()` Copy counts source and
destination payload once each. This is not a physical DDR bus-traffic counter.

Memory results affected by the old truncated denominator can decrease. This
corrects an accounting defect, not a new score formula or workload, so the
release remains a patch. Use Beta 5 for new memory comparisons and disclose the
timing correction when comparing with older versions. No claim is made that
Android scheduling requests guarantee peak clocks or theoretical bandwidth.

All 11 result IDs remain present. The UI displays SQL Insert, Update, Delete;
their established IDs remain 9, 11, 10 respectively.

| Sequential read/write, IDs 1/2 | Direct, 1 MiB, QD8, one submitting thread | Buffered Q1T1 route selection simulated |
| 4K Q1T1 read/write, IDs 3/4 | Direct, QD1, one thread | Existing synchronous implementation retained |
| 4K Q8T1 read/write, IDs 5/6 | Direct AIO, QD8, one submitting thread; observed max outstanding 8 | Unavailable route selection simulated when Direct AIO is absent |

The new native route test also checks that the raw scratch file is absent at
terminal state. Write flushes and SQL cleanup finish before the final result.
The Buffered fallback branch is a routing simulation, not a forced Buffered
end-to-end device benchmark; Direct I/O is available on the connected phone.

## Real-device boundary

Device: OnePlus PJZ110 / Snapdragon 8 Elite / Adreno 830. Debug and Release
validation in this record applies only to this physical phone. It is functional
regression testing, not a cooled, controlled cross-version performance study.

Ten-core/legacy topology fixtures, denied-affinity behavior, distorted GPU
timestamps, cross-module controller faults and fallback routing are simulated
regressions. Xring O1, Exynos 2600, Snapdragon 865, Kirin 990/980 and other GPU
driver families were not available for direct Beta 5 testing.

### Attestation and immutability (Section 12.4)

The existing local-build exception is carried forward: there is no repository
release workflow issuing an APK build attestation. The repository's
`immutable-releases` API reports `enabled: false, enforced_by_owner: false`;
Beta 5 does not change repository security settings. Do not describe a checksum
as an attestation.

Minimum evidence is the annotated source tag, exact source commit, environment
inventory, certificate, tested APK and SHA-256 sidecar. Prepare and verify both
assets in Draft, publish as Pre-release and not Latest, then re-read the public
author, tag and asset metadata. Never replace public tags or APKs. Add a pinned
build/attestation workflow and review immutable releases before Stable.

There is no dependency change requiring a new dependency inventory in this
patch. A complete SBOM and cross-vendor device matrix remain pre-Stable work.
