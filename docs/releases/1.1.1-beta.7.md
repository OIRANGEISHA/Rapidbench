## Fixes / 修复

- CPU ranking now uses comparable evidence across all detected CPUs: complete
  capacity, otherwise complete maximum frequency, otherwise a labelled unknown
  fallback. Incomplete capacity data cannot silently dominate a different core's
  frequency-only rank. Constant cluster/policy IDs no longer hide distinct ranks.
- Frequency-derived/unknown automatic Single choices have explicit warnings.
  Application Multi still uses all present cores, independently of legacy selectors.
- GPU baseline pipelines are initialized independently. Unavailable items are
  identified and skipped by All; native FP16 pipeline rejection may use labelled
  FP32 emulation. Optional variants can fall back to the baseline. Strict output
  validation remains; submission/device faults stop global context reuse.
- Per-item GPU state, reason, run ID and timing counts distinguish real completion,
  unavailable items, failure and partial results. The timing summary includes all
  current-run batches, not just the last one. Raw GPU observations are not validated
  elapsed time.
- Memory rechecks available CPUs after warm-up, with at most two re-preparations,
  then freezes worker membership before timing. Restrictions/instability are visible.
- Extremely short or scheduler-delayed CPU runs could show Peak below the whole-run
  final-score fallback. Peak now includes that measured interval when windows are
  insufficient, and on stop. The main score formula is unchanged.
- 统一 CPU 排名依据并提示未知/推断信息；GPU 按项目隔离不可用管线并明确 FP16 回退；
  内存预热后有界重检可用核心；修复短测试 Peak 边界问题。没有厂商分数倍率或机型白名单。

Detailed behavior: [compatibility record](../compatibility-beta7.md).
