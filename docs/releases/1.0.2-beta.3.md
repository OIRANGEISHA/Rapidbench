## Goal

Add an About App entry to the Device module without changing the CPU, GPU,
memory, or storage benchmark implementations.

## Scope

- Display the application label, installed package version name, and actual
  installed version code.
- Display the RapidBench repository URL:
  `https://github.com/OIRANGEISHA/Rapidbench`.
- Open the repository in the device browser when the user taps the GitHub
  action.
- Use Android's native `ACTION_VIEW` intent; do not add a Flutter dependency.
- Show a user-readable message when no browser can open the link.
- Require explicit Release signing environment variables instead of silently
  falling back to an arbitrary Debug key.
- Reuse the retained Beta signer from `1.0.1-beta.2` and keep the single-arm64
  public APK's final Android version code equal to the pubspec build number.

## Compatibility

- The package information uses Android `PackageManager` APIs available on the
  existing minimum Android version.
- Browser launch uses a fixed HTTPS URL and does not require RapidBench to add
  the Android network permission.
- Benchmark algorithms, workloads, timing, scoring, and result formats are not
  changed in this iteration.

## Real-device validation notes

The connected device originally had `1.0.1-beta.2` with version code `4016`.
The first Beta 3 build used version code `2017`, which Android correctly rejected
as a downgrade. Beta 3 was corrected to monotonically increasing version code
`4017` and rebuilt before validation continued.

Because the installed Beta 2 used a different certificate from the requested
Debug build, Android rejected an in-place update. After explicit user approval,
Beta 2 was uninstalled (clearing RapidBench local app data) and Beta 3 Debug was
installed successfully. The About App page and browser handoff then passed on the
PJZ110. The activity intent recorded the exact URL
`https://github.com/OIRANGEISHA/Rapidbench`, and Microsoft Edge became the
foreground browser.

The signed Release APK was subsequently installed with ADB's `-t` allowance.
Without that allowance, ColorOS routed the ADB session through its interactive
installer security flow and returned vendor error `-99`; APK parsing, free space,
signature verification, and the second installation all passed. The public APK
itself is a normal non-debuggable Release variant.

## Release waiver

### Retained Beta signing certificate

- Clause: Section 10 recommends a protected Beta or production keystore for
  externally distributed Beta builds.
- Reason: Beta 2 already established the retained Android test certificate as
  the package signer; Beta 3 reuses it so Android can perform an in-place update.
- Risk: This certificate is not suitable for a trusted Stable or store release.
- Mitigation: Release signing is explicit and fails closed when the required
  environment variables are absent; the certificate fingerprint is verified
  against Beta 2 before publishing.
- Plan: Migrate to a protected long-lived release key before the first Stable
  release and document that migration for testers.

### Artifact attestation

- Clause: Section 6 recommends provenance or artifact attestation for Beta
  releases.
- Reason: This repository does not yet contain a GitHub Actions release workflow
  capable of issuing an attestation for locally built Android artifacts.
- Risk: GitHub cannot independently attest the local build environment.
- Mitigation: Publish the exact APK SHA-256 sidecar, certificate fingerprint,
  source tag, commit, ABI, version metadata, and validation record.
- Plan: Add a pinned GitHub Actions Android release workflow and artifact
  attestation before the first Stable release.
